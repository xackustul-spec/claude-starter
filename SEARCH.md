# Помощник по поиску — чем и где искать

Короткая карта: что взять под конкретную задачу. Глубокий список каталогов, кому верить и
как проверять безопасность — `.claude/skills/tool-scout/sources.md`.

Правило простое: интернет — первый шаг, а не последний. Владелец не обязан говорить
«поищи»: если в ответе есть версия, цена, имя пакета, настройка, «как сейчас принято»,
незнакомое имя или новость — сначала поиск, потом ответ.

## Что чем искать
| Нужно | Чем | Как |
|---|---|---|
| Версии, API, флаги библиотеки | Context7, если подключён; иначе официальная документация | спросить документацию по имени библиотеки и версии |
| Свежие факты, цены, «как сейчас принято» | веб-поиск | запрос словами задачи + год |
| Ошибка, странное поведение, обход | GitHub Issues и Discussions библиотеки, Stack Overflow, Reddit | искать текст ошибки дословно, затем своими словами |
| Скиллы для агента | `npx skills find <запрос>`, каталог skills.sh | ставить `npx skills add <автор>/<репо>` (нужен Node) |
| MCP-серверы | `claude.com/connectors`, github.com/mcp, hub.docker.com/mcp, registry.modelcontextprotocol.io | `curl "https://registry.modelcontextprotocol.io/v0/servers?search=<слово>"` |
| Плагины Claude Code | `/plugin` → Discover (вводит владелец) | каталоги Anthropic — первыми |
| Компоненты, темы, готовый вид | витрина самой библиотеки; у shadcn — `shadcn mcp init`, ищет сразу по всем реестрам; список реестров `https://ui.shadcn.com/r/registries.json` | ставить одной командой, проект не переписывать |
| Готовые шаблоны и стартеры | GitHub: `<библиотека> template`, `starter`, `dashboard`, `admin`; topic-страницы; `awesome-<библиотека>` | смотреть дату обновления и версию стека |
| Пакет: существует ли, жив ли | npm, PyPI, страница репозитория | имя пакета проверять всегда: придуманные имена регистрируют злоумышленники |

## Правила поиска
- Нужного каталога здесь нет — найти сам каталог: описать задачу словами и поискать
  «<тема> registry / catalog / marketplace / awesome / MCP». Найденное дописать сюда с датой.
- Проверять первоисточник — репозиторий, npm, сайт автора, — а не пересказ выдачи и не
  описание в каталоге.
- Каталог не открылся или молчит — так и сказать владельцу; не пересказывать его описание
  и не называть «крупнейшим».
- Цифры звёзд, установок и размеров — повод посмотреть, не доказательство.
- Искать вширь: 5–7 разных по подходу вариантов полезнее одного «правильного».
- Ничего не устанавливать без `compat-check` и «да» владельца (при полном доверии — сам,
  с записью в `docs/ai/TOOLS.md`).
- Что нашлось и пригодилось — строкой в `docs/ai/KNOWLEDGE.md`; что отвергли и почему —
  в `docs/ai/DECISIONS.md`, чтобы не искать это второй раз.

## Как выдавать выбор
Когда: владелец просит найти готовое, показать варианты, «сколько такого есть», или его
не устроило сделанное своими руками. Порядок обязательный, шаги не переставлять.

1. Слово владельца понимать буквально. Шаблон ≠ библиотека ≠ тема ≠ компонент ≠ скилл.
   Шаблон — чужая законченная работа: её открывают и видят целиком. Библиотека — кирпичи,
   из которых собирают сами. Не ясно, что имелось в виду — один вопрос с примерами, до поиска.
2. Источник — реестр с программным доступом, а не память и не один каталог: GitHub API
   (поиск по темам и словам), npm, PyPI, официальные каталоги. Не меньше трёх источников
   и трёх разных формулировок запроса.
3. У каждого варианта только проверяемые поля, взятые из API: имя, звёзды, лицензия, дата
   последней правки, ссылка на репозиторий, адрес живой витрины. Ничего из рекламного
   описания и ничего «на глаз». Поля нет — так и писать «нет», не додумывать.
4. Давать столько, сколько попросили. Сказали «сто» — значит сто. Урезать «до лучших» —
   это решать за владельца то, о чём он не просил. Число не названо — не меньше двадцати,
   если столько есть.
5. Показывать, а не описывать. Живая витрина автора важнее любого своего превью. Витрины
   нет — это минус варианту в таблице, а не повод рисовать имитацию.
6. Своими руками не делать то, что уже сделано: один запрос к реестру полезнее десяти
   превью, написанных вручную.
7. Выдача в два слоя: страница `docs/ai/previews/<тема>.html` с поиском, отбором и ссылками
   на витрины — и в самом ответе сводка по стеку плюс верхушка списка таблицей, чтобы было
   видно без открытия файла. Путь к странице — полный, от диска.
8. Отбор под проект — после показа всего, отдельным коротким разделом: 2–3 варианта, у
   каждого одна строка «почему подходит» и одна «чем за это платим».
9. Назвать свой выбор прямо: «моё мнение» — один вариант и причина в одну-две строки,
   второй рядом как запасной. Нейтральный список без своего мнения — половина работы:
   владелец просил помощи с выбором, а не картотеку. Мнение даётся строкой, без уговоров,
   решение остаётся за владельцем; свой выбор объяснять делом (стек, сопровождение,
   цена правок), а не звёздами и не красотой витрины.
10. Закончить одним конкретным шагом выбора — «скажете номер, ставлю и перевожу», — а не
   списком новых вопросов.

## Деньги
- Бесплатное — по умолчанию.
- Бесплатное не хуже платного — берём бесплатное. «Солиднее», «популярнее», «с поддержкой»
  причиной платить не считается.
- Платное предлагать, только если бесплатного нет совсем или оно объективно хуже по делу;
  назвать цену и что именно даёт доплата. Цены на странице нет — так и писать.
- Платные варианты — отдельным списком ниже бесплатных, не вперемешку.
- Лицензия — проверяемое поле: MIT, Apache, GPL или «не указана». «Не указана» считать
  несвободной, пока не доказано обратное.
