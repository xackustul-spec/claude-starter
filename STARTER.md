# claude-starter v2 — самообучающийся набор для любого проекта

Кладёте набор в папку проекта (новую или с работающим кодом) — Claude Code сам понимает,
как работать: разбирает задачу и задаёт только нужные вопросы, предлагает готовый каркас
и инструменты, ищет в интернете и проверяет совместимость без напоминаний, перед правкой
отвечает «что я сломаю», после — проверяет свежими глазами, подписывает код и ведёт
документы проекта в том же шаге, учится на ошибках. Работает на Windows, Linux и macOS.

Все запросы и команды ниже (`/kit-setup`, `/context` и т.п.) вводятся **в поле сообщения
Claude Code** — в приложении Claude на компьютере (раздел Code) или в терминале с `claude`.
Команды для терминала, если нужны, Claude выполнит сам — достаточно попросить.

## Пять слов, которые встретятся
- **CLAUDE.md** — ядро: файл, который Claude читает в начале каждого сеанса.
- **Скилл** — пошаговая инструкция на конкретную задачу; Claude подключает её сам или вы командой `/имя`.
- **Хук** — маленькая программа-защита: срабатывает автоматически до или после действия Claude.
- **MCP / коннектор** — подключаемый источник данных или инструмент для Claude (например, Context7 — свежая документация библиотек).
- **Субагент** — отдельный Claude с чистой памятью: проверяет работу основного, не читая переписку.

## Что внутри

## Как устроено (почему ядро короткое)
| Где | Когда Claude читает | Что там |
|---|---|---|
| `CLAUDE.md` | всегда | только то, что нужно в любой задаче |
| `docs/ai/PROFILE, STATE, KNOWLEDGE, LESSONS` | всегда (подключены к ядру) | короткие: кто мы, где мы, факты, уроки |
| `.claude/rules/*.md` | когда открывает или записывает файлы подходящего типа | код, интерфейс, безопасность |
| `.claude/skills/` | когда задача подходит или по `/имя` | пошаговые процедуры |
| `.claude/agents/` | когда Claude поручает проверку | субагенты в чистом контексте |
| остальное в `docs/ai/` | по указателю INDEX.md, когда нужно | ТЗ, решения, инструменты, превью |

Чем короче ядро, тем точнее Claude его соблюдает. Новые правила Claude сам раскладывает
по этим местам; в крупных проектах ещё создаёт вложенные `CLAUDE.md` в подпапках
(подгружаются, когда работает с ними) — так набор распространяется по проекту.

## Установка

### Через GitHub (проще всего)
Один раз выложите набор в свой репозиторий на GitHub (публичный: секретов в наборе нет).
Дальше в любом проекте откройте Claude Code и напишите:
`Установи набор https://github.com/<логин>/claude-starter — инструкция в INSTALL.md`
Claude скачает набор, перенесёт его, не заменяя ваши файлы, и начнёт задавать вопросы.

### Без GitHub, из папки на компьютере
Распакуйте архив один раз в постоянную папку, например `C:\claude-starter` (это ваш «главный»
набор). В каждом проекте напишите Claude:
`Установи набор из папки C:\claude-starter — инструкция в INSTALL.md`
Не копируйте набор из одного проекта в другой: уроки проекта копятся в его `docs/ai`, а не в наборе.

### Обновления
При старте сеанса Claude раз в сутки сверяет версию набора в проекте с GitHub. Вышла новая —
предложит обновить; после «да» заменит только файлы набора, которые вы не меняли, про изменённые
спросит, документы проекта не тронет. Выпустить новую версию: изменить файлы в репозитории,
увеличить номер в `VERSION` и дописать строку в `CHANGELOG.md`.

### Общие уроки из всех ваших проектов
Каждый урок Claude помечает «общий» или «проект». Если при установке вы разрешили отправку,
общие уроки молча уходят файлами в папку `inbox` источника — из всех проектов в одно место,
неважно, лежит проект на компьютере или на сервере: отправляет тот Claude, который с проектом
работает. Источник — ваша папка набора или ваш репозиторий на GitHub.
Время от времени откройте Claude Code в папке набора и введите `/kit-harvest`: Claude объединит
повторы, предложит правки правил, после «да» внесёт их, поднимет версию. Проекты увидят
обновление и обновятся после вашего «да»; их собственные правила останутся.

### Оценить, ничего не меняя
Отправьте Claude запрос из `AUDIT-PROMPT.md` (набор должен лежать в `_starter/`).
Получите отчёт: что набор изменит, улучшит, сломает. Ничего не применяется.

### Что происходит при установке
Claude делает коммит «до набора», переносит файлы: ваш `CLAUDE.md` остаётся, набор
вписывается в него отдельным блоком после вашего «да»; ваши настройки и одноимённые файлы не
заменяются; `README.md` не трогается. Затем спрашивает профиль, проверяет защиты, делает коммит
«набор подключён» и переходит к разбору проекта. Откат: «верни проект к коммиту до набора».

Linux / macOS: хуки работают через `bash` и `python3` (на macOS — Xcode Command Line Tools);
Claude при установке сам подставит нужные настройки. Без `python3` хуки молчат и всё разрешают.
На Windows хуки работают через встроенный PowerShell; Python нужен только для тестов хуков.

Проверка после установки: `/context` — в «Memory files» есть CLAUDE.md, PROFILE, STATE,
KNOWLEDGE, LESSONS, INDEX; наберите `/` — в списке видны скиллы набора; попросите Claude
«прогони тесты хуков» — итог «всё в порядке».

## Профиль: доверие и ответы
Claude спросит его при установке и запишет в `docs/ai/PROFILE.md`.

| Доверие | Claude делает сам | Спрашивает | Чем обеспечено |
|---|---|---|---|
| осторожное | только читает | любые правки и команды | `defaultMode: default` в `.claude/settings.local.json` |
| обычное (по умолчанию) | правит файлы | команды, установки, опасное, правку своих инструкций | `acceptEdits` в настройках набора + хуки |
| полное | всё, в т.ч. установки (после проверки совместимости, с записью в TOOLS.md) и правку своих правил (с отчётом) | только необратимое: удаление данных, деплой, миграции и сброс баз, переписывание истории git, остановку служб, секреты, изменение разрешений и хуков; деньги и сообщения людям — по правилу в CLAUDE.md | режим Auto + `CLAUDE_TRUST_LEVEL=full` |

Как включить **полное доверие** (Claude сделает это при установке, если выберете):
1. `.claude/settings.local.json` с `{"env": {"CLAUDE_TRUST_LEVEL": "full"}}` — личный файл, в git не
   попадает, поэтому при переносе проекта в другую папку его не будет: Claude заметит это в начале
   сеанса и создаст заново сам, не спрашивая.
2. Режим Auto: в приложении Claude — переключатель режима у поля ввода (запоминается для
   папки); в терминале — `claude --permission-mode auto`. Запись `auto` в настройках
   проекта не действует — так устроен Claude Code.
3. В `docs/ai/PROFILE.md` — «Доверие: полное».

При любом доверии остаются: блок хрупких ssh-команд и кириллицы в коде (хуки), вопрос перед
удалением данных, force-push, чтением секретов и изменением разрешений и хуков (хуки и
правила `ask` в settings.json). Про деньги и сообщения людям технической защиты нет — это
правило CLAUDE.md.

Ответы: «сжато» — первая строка «режим — итог», дальше формат «Название — что это, одной
фразой». Дополнительно можно включить встроенный стиль «Concise»: `/config` → Output style
(или строка `"outputStyle": "Concise"` в `.claude/settings.local.json`).

## Как это работает в жизни
1. **Начало сеанса** — хук показывает STATE.md и git; Claude продолжает с «Следующего шага»,
   не перечитывая переписку. Всё нужное из разговора он сразу пишет в KNOWLEDGE.md.
2. **Простой вопрос** — просто ответ. **Опечатка или текст** — правка и проверка без
   протокола. **«Хочу сделать приложение для…»** — `project-intake`: понять, спросить только
   блокирующее (до 3 раундов, с рекомендуемым вариантом), ТЗ с вашими цитатами, карта
   возможностей → `project-foundation` (все библиотеки сразу в HTML-галерее; одна библиотека —
   все её темы, выбор темы в настройках) → `tool-scout` (стартовый набор под тип проекта,
   только проверенные источники, установка после «да»).
3. **Изменение** — `safe-change`: субагент ищет, что сломается; все места сразу; старое
   нигде не читается; другие субагенты проверяют (тесты, запуск, экраны); документы и шапки
   в том же шаге — хук не даст закончить ответ иначе.
4. **Самообучение** — ошибка → урок-кандидат; повтор → активный; ещё повтор → хук или тест.
   Нужен новый документ — Claude сам заводит его в docs/ai (переполнился — делит на части `_2`, `_3`) и описывает в указателе INDEX.md; правило для части кода —
   в `.claude/rules`; процедура — скилл; крупная подсистема — вложенный CLAUDE.md.
5. **«Заметил, не сделал»** — в конце большого ответа Claude предлагает 1–3 улучшения,
   которых вы не просили, но ничего сверх задачи не делает без «да».

## Как понять, что набор работает
- Начало сеанса: первое сообщение Claude опирается на состояние проекта, а не на вопрос «что делаем?».
- Первая строка ответа называет режим («просто ответ» / скилл) и итог.
- Вы хотя бы раз не согласились с «Рекомендую» — значит, вопросы были по делу.
- В SPEC.md ваши слова стоят в кавычках.
- Попытка записать файл с кириллическим именем переменной блокируется.
- После правки кода Claude в том же ответе показывает вывод проверки и обновляет STATE.md.
- `/kit-audit health` раз в месяц — таблица «проверка → ок / проблема».

## Совместимость с другими наборами
Встроенная автопамять Claude в проекте выключена (`autoMemoryEnabled: false`): всё, что
нужно помнить, живёт в docs/ai и в git. Фреймворки процесса (autopilot, Superpowers,
Spec Kit и т.п.) — не больше одного на проект и только по вашей просьбе; их документы
подключаются в указатель INDEX.md, а не копируются. Встроенные команды Claude Code (`/debug`,
`/code-review`, `/verify`) с набором не конфликтуют. Файлы переводов с русскими ключами
кладите в `locales/`, `i18n/` или `lang/` — там хук их не блокирует.

## На чём основано
Документация Claude Code (память и CLAUDE.md, правила, скиллы, хуки, субагенты, разрешения,
режимы) — https://code.claude.com/docs/en/ · опыт похожих подходов (Cline Memory Bank,
Every Compound Engineering, Kiro steering, обучаемые правила Cursor, autopilot, Superpowers,
набор Мэтта Покока, Spec Kit) · исследования: агенты редко задают уточняющие вопросы,
пока это не сделано отдельным шагом; документы, пересказывающие очевидное из кода, ухудшают
результат; память, переписанная целиком, теряет детали; в открытых каталогах есть вредоносные
скиллы и коннекторы — поэтому проверка кода перед установкой обязательна.
