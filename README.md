# claude-starter

Набор инструкций для **Claude Code**: кладётся в любой проект — новый или уже работающий — и
задаёт Claude порядок работы. Claude сам разбирается в проекте, задаёт нужные вопросы,
подбирает библиотеки и инструменты, проверяет свои изменения, ведёт документы проекта и
учится на ошибках. Работает на Windows, Linux и macOS.

Установка одной строкой — в Claude Code, открытом в папке проекта:

    Установи набор https://github.com/xackustul-spec/claude-starter — инструкция в INSTALL.md

---

## 1. Зачем это нужно

Claude в каждом новом разговоре начинает с чистого листа. Из-за этого в длинных проектах
повторяются одни и те же проблемы: он забывает договорённости, переписывает то, что уже
работало, ставит пакеты без спроса, пишет «готово» без проверки, а описание проекта
устаревает, потому что обновляется «когда-нибудь потом».

Набор закрывает это тремя способами:

1. **Память проекта.** Всё важное лежит в коротких документах в папке `docs/ai`, а не в
   переписке. Новый разговор начинается с состояния проекта, а не с пересказа чата.
2. **Порядок работы.** На каждый тип задачи — своя пошаговая инструкция (скилл): разбор
   нового проекта, новая функция, ошибка, изменение, поиск решения, выбор инструментов.
3. **Автоматические защиты (хуки).** Небольшие скрипты, которые срабатывают сами: блокируют
   опасное, спрашивают перед установками, не дают закончить ответ, пока не обновлены документы.

## 2. Как это работает

```
ваш запрос
   │
   ├─ начало сеанса: хук показывает Claude состояние проекта и git
   │
   ├─ Claude выбирает режим по разделу «Что запускать» в CLAUDE.md
   │     простой вопрос → ответ
   │     новая функция → new-feature      ошибка → fix-bug
   │     изменение → safe-change          установка → compat-check
   │
   ├─ во время работы:
   │     хук guard-shell — вопрос перед установкой, удалением, чтением секретов
   │     хук pre-write  — блок русских имён в коде, вопрос перед правкой инструкций,
   │                      подсказка правил для этого типа файлов
   │
   └─ конец ответа: хук check-docs — код изменён, а документы нет? вернуть и дописать
```

Ядро `CLAUDE.md` короткое (~110 строк): Claude читает его всегда, поэтому там только то, что
нужно в любой задаче. Остальное подгружается по мере надобности: правила — когда Claude
работает с файлами этого типа, скиллы — когда подходит задача, документы — по указателю.

## 3. Что появится в вашем проекте

| Что | Для чего |
|---|---|
| `CLAUDE.md` | ядро: правила, маршруты задач, порядок работы с документами |
| `docs/ai/` | память проекта: состояние, знания, ТЗ, решения, уроки |
| `.claude/rules/` | правила по типам файлов (код, интерфейс, безопасность) |
| `.claude/skills/` | пошаговые инструкции на каждый тип задачи |
| `.claude/agents/` | проверяющие с чистой памятью |
| `.claude/hooks/` | автоматические защиты |
| `.claude/settings.json` | разрешения и подключение защит |
| `.mcp.json` | Context7 — свежая документация библиотек |
| `STARTER.md` | подробное руководство для владельца |

Ваши файлы не заменяются: при совпадении имён набор ложится рядом (`CLAUDE.starter.md`,
`settings.starter.json`) и сливается только после показа разницы и вашего «да». `README.md`
проекта не трогается, в `.gitignore` дописываются недостающие строки. Перед установкой
делается коммит «до набора» — к нему всегда можно вернуться.

## 4. Описание всех файлов

### Корень набора
| Файл | Что это |
|---|---|
| `CLAUDE.md` | ядро набора. Разделы: «Никогда» (запреты), «Старт сеанса», «Что запускать» (маршруты задач), «Доверие», «Как отвечать», «Главные правила», «Документы», «Когда заводить новый документ» |
| `STARTER.md` | полное руководство: установка, профиль доверия, как всё работает, как понять, что набор работает |
| `INSTALL.md` | инструкция установки для самого Claude: что скачать, куда положить, что выполнить |
| `README.md` | этот файл |
| `VERSION` | номер версии набора |
| `CHANGELOG.md` | что изменилось в каждой версии |
| `AUDIT-PROMPT.md` | готовый запрос: оценить набор в проекте, ничего не меняя |
| `gitignore.starter` | строки, которые дописываются в `.gitignore` проекта |
| `.mcp.json` | подключение Context7 (документация библиотек) |
| `inbox/` | входящие общие уроки из проектов (в проект не копируется) |

### Документы проекта — `docs/ai/`
| Файл | Что хранит | Когда Claude читает |
|---|---|---|
| `PROFILE.md` | паспорт проекта, зоны «не трогать», профиль: доверие, подробность ответов, показывать ли код | всегда |
| `STATE.md` | что работает, что в работе, следующий шаг, допущения, тупики | всегда |
| `KNOWLEDGE.md` | договорённости, термины, факты об окружении, таблица доступов, найденные ответы | всегда |
| `LESSONS.md` | уроки с пометкой «общий» или «проект»: кандидат → активен → закрыт хуком или тестом | всегда |
| `INDEX.md` | указатель: какие документы есть, какие данные в каждом, когда читать | всегда |
| `PROJECT_MAP.md` | где что должно лежать и почему, проверенные команды запуска и тестов | перед работой с кодом |
| `SPEC.md`, `specs/` | ТЗ: требования с вашими цитатами, анти-цели, эталон, данные | перед задачей по функциям |
| `DECISIONS.md` | почему выбрано именно так | перед сменой подхода |
| `TOOLS.md` | что установлено, зачем, версия, как удалить | перед установкой |
| `FOUNDATION.md` | библиотека оформления, темы, каркас, витрина компонентов | при работе с интерфейсом |
| `previews/` | HTML-превью и галереи вариантов оформления | при выборе вида |
| `solutions/` | разборы решённых сложных проблем, по одной на файл | поиском при похожей ошибке |

Размер документов ограничен (например, `STATE.md` — 60 строк). При переполнении Claude выносит
тему в отдельный файл или делает продолжение `_2`, `_3` и описывает каждую часть в `INDEX.md`.

### Правила — `.claude/rules/`
Подгружаются, когда Claude открывает или пишет файл подходящего типа.

| Файл | О чём |
|---|---|
| `code.md` | только латиница в именах, прибитые версии, идемпотентность, не подавлять ошибки, команды на сервер — скриптом |
| `code-headers.md` | первая строка каждого файла кода: `Назначение: …`; из этих строк собирается карта проекта |
| `security.md` | проверка прав на сервере, секреты только в `.env`, параметры в запросах к базе, персональные данные, логи без паролей |
| `ui.md` | одна библиотека компонентов, все её темы, цвета только из темы, состояния экранов, проверка в тёмной теме и на телефоне |

### Проверяющие — `.claude/agents/`
Отдельные Claude с чистой памятью: не видят переписку, не могут править файлы.

| Файл | Когда работает |
|---|---|
| `impact-analyst.md` | до изменения: что сломается, где ещё используется, что обновить |
| `change-verifier.md` | после: соответствие плану, старые пути, тесты, запуск проекта, документы |
| `ui-checker.md` | после: экраны, ошибки в консоли, темы, ширина телефона, сравнение «до/после» |

### Защиты — `.claude/hooks/`
Две одинаковые версии: `.ps1` для Windows, `run.sh` + `kit_hooks.py` для Linux и macOS.

| Файл | Что делает |
|---|---|
| `session-start.ps1` | в начале сеанса показывает состояние проекта и git, сообщает о новой версии набора |
| `turn-start.ps1` | снимок репозитория в начале хода — чтобы знать, что изменено именно сейчас |
| `guard-shell.ps1` | вопрос перед установкой, удалением, миграциями, деплоем, чтением секретов; блок хрупких ssh-команд |
| `pre-write.ps1` | перед записью файла: блок русских имён в коде, вопрос перед правкой инструкций, подсказка правил |
| `check-python.ps1` | проверка синтаксиса `.py` после записи |
| `check-docs.ps1` | в конце ответа: код изменён, а документы или подписи файлов — нет? не даёт закончить |
| `scan.ps1` | проверка русских имён в готовых файлах, без записи |
| `kit-version.ps1` | версия набора: записать отпечатки файлов, показать план обновления |
| `kit_common.ps1` | общая логика всех Windows-защит |
| `kit_hooks.py`, `run.sh` | те же защиты для Linux и macOS |
| `tests/` | ~850 проверочных случаев и сценарии: обе версии должны вести себя одинаково |
| `README.md` | подробности по каждой защите и как её отключить |

### Инструкции на задачи — `.claude/skills/`
| Скилл | Когда включается |
|---|---|
| `kit-setup` | первая установка набора в проект |
| `kit-update` | обновление набора до новой версии |
| `kit-audit` | проверка набора в проекте; оценка до установки |
| `kit-timing` | разбор хронометража: куда уходит время и токены, что сократить |
| `kit-share` | отправка общего урока в набор |
| `kit-harvest` | сбор уроков из проектов и улучшение самого набора |
| `project-intake` | новый проект или крупная новая часть: понять, спросить, записать ТЗ |
| `project-foundation` | каркас интерфейса: показ всех вариантов оформления, темы, витрина |
| `project-adopt` | подключение к уже работающему проекту без поломок |
| `tool-scout` | подбор библиотек, плагинов, коннекторов под задачу; проверка безопасности |
| `compat-check` | совместимость и актуальность перед любой установкой |
| `new-feature` | новая функция: ТЗ с цитатами, план, работа, приёмка |
| `fix-bug` | ошибка: воспроизвести, найти причину, минимально починить, доказать тестом |
| `find-solution` | ошибка не уходит: поиск по документации, GitHub Issues, форумам |
| `safe-change` | изменение нескольких файлов, переименование, данные, конфигурация, общий стиль |
| `project-memory` | обновление документов проекта в конце задачи |

## 5. Доверие

| Уровень | Claude делает сам | Спрашивает |
|---|---|---|
| осторожное | только читает | любые правки и команды |
| обычное | правит файлы | команды, установки, опасное, правку своих инструкций |
| полное | всё, включая установки и правку своих правил | необратимое: удаление данных, деплой, миграции, переписывание истории git, секреты, изменение своих защит |

Уровень выбирается при установке, меняется по вашей просьбе.

## 6. Версии и обновления

У набора есть номер версии. При установке он записывается в проект вместе со ссылкой на
источник. Раз в сутки Claude сверяет версию с этим репозиторием и, если вышла новая,
предлагает обновиться. После «да» заменяются только файлы набора, которые вы не меняли;
про изменённые он спрашивает, документы проекта не трогает.

## 7. Обратная связь

Каждый урок помечается «общий» или «проект». Общие уроки можно отправлять в папку `inbox`
этого репозитория — из всех проектов в одно место. Команда `/kit-harvest` в папке набора
собирает их, объединяет повторы и предлагает, что улучшить в наборе.

## 8. Требования

Claude Code (приложение Claude на компьютере или `claude` в терминале) и git. Python 3 нужен
для защит на Linux и macOS, на Windows — только для запуска тестов. Без Python на Linux
защиты молчат и всё разрешают, остальная часть набора работает.

## 9. Откат

Установка и каждое изменение — отдельными коммитами. Чтобы всё вернуть, скажите Claude:
«верни проект к коммиту до набора».
