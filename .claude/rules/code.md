# Правила кода

- IMPORTANT: имена файлов, папок (включая папку самого проекта), маршрутов, переменных
  (и в shell), функций,
  ключей JSON, заголовков HTTP — только латиница. Русский — в текстах
  интерфейса, строках и комментариях.
- Команды на удалённый сервер — скриптом в файле (LF, ASCII-имя) → scp →
  `ssh <сервер> 'bash /tmp/<файл>.sh'`. Без heredoc, `$(...)` и вложенных
  кавычек через PowerShell. Код возврата — от нужной команды (`set -euo pipefail`).
- Версии зависимостей прибиты, `latest` не используется. Новые пакеты —
  только существующие, с историей и репозиторием (проверить).
- Повторный запуск не плодит дубли (записи, задачи, находки) — идемпотентность.
- Тестовые данные помечать и убирать после проверки.
- Неиспользуемые зависимости и мёртвый код — удалять (с «да»).
- Сгенерированные файлы (клиенты ORM, сборка) — перегенерировать после
  изменения схем, иначе ложные ошибки.
- Не подавлять ошибки (`except: pass`, отключение проверок) вместо исправления причины.
- Тест, который просто повторяет объявление или конфиг и меняется вместе с кодом, — не
  защита, а балласт; тестировать поведение на стыке частей.
- У скрипта, который правит файлы, не бывает безобидного запуска «посмотреть, что получится»:
  для осмотра писать отдельный скрипт, который только читает и печатает. Правящий скрипт
  запускать, когда уже решено менять, и после — проверять результат, а не отчёт скрипта.
- Бэкап считается сделанным только после проверки самого архива (`gzip -t`, размер, число строк)
  и до первого изменения данных. Пустой архив от сломанной команды выглядит как успешный.
- Массовое переименование задевает текст: после него искать английские слова внутри русских
  фраз и проверять по отрисованной странице, а не по исходнику.
- Команды в документах и скриптах — только запущенные и проверенные.
- IMPORTANT: код раскладывается так же, как документы, — чтобы на правку читать одно место, а не
  всё. Один файл — один экран или одна область (маршруты экрана, его шаблон, его стиль, его скрипт);
  точка входа короткая — подключает части и общее. Стили: база → тема (цвета, размеры, шрифты одним
  местом) → общие компоненты (таблица, кнопки, легенда) → файл экрана только для того, что есть лишь
  на нём; **один селектор живёт в одном файле**, иначе правка в одном месте ломает другое. Файл
  кода перерос ~1000 строк, селектор или функция нашлись в двух файлах — это сигнал разделить
  (`project-restructure`, «Разделение по экранам»), хук напоминает. Документ вида — семейство:
  нулевой файл маршрут, общие правила часть, каждый экран своя часть.
- IMPORTANT: ни один вызов не ждёт человека. Команда, которой нужен ввод (редактор, пейджер, `ssh`
  без команды, `git commit` без `-m`, `npm init` без `-y`, `psql` без запроса) — не запускается
  (хук отказывает): переписать с ключом «без вопросов». Долгое (сборка, прогон, обход, перенос)
  — только с `timeout` и в фоне с логом: запустил → проверил вывод → продолжил, а не сидел рядом.
  Действие, на которое нужно разрешение владельца, — спросить словами до запуска, а не упираться
  в окно разрешения, когда его нет рядом. Вызов ждал больше 10 минут — хук скажет об этом в
  следующем ходе; в ответе одной строкой: что висело и чем заменено.
- Найденное совпадение читать целиком в его границах: от открывающего тега до закрывающего,
  от начала строки до конца, от начала функции до её конца. Совпало имя (`name=`, `id=`, ключ,
  переменная) — сначала посмотреть, внутри чего оно стоит, и только потом делать вывод.
  Вывод по одному совпадению без окружения — не факт, а догадка.
- IMPORTANT: процедура из нескольких команд, которая повторилась третий раз (выкладка, сборка, подъём
  тестовой копии, снимок экрана, бэкап), — это скрипт, а не список шагов в документе. Один запуск
  делает все шаги и последней строкой печатает итог словом («ИТОГ: ВЫЛОЖЕНО — md5 совпали» /
  «ИТОГ: НЕ ВЫЛОЖЕНО — …») с кодом возврата. В `PROJECT_MAP.md` — одна строка: как запустить.
  Выполнять процедуру руками по шагам, когда скрипт есть, запрещено: каждая команда — отдельное
  обращение к модели и ожидание владельца. Скрипта нет — сначала написать его, потом запускать.
