# Правила кода

- IMPORTANT: имена файлов, папок (включая папку самого проекта), маршрутов, переменных
  (и в shell), функций,
  ключей JSON, заголовков HTTP — только латиница. Русский — в текстах
  интерфейса, строках и комментариях.
- Команды на удалённый сервер — скриптом в файле (LF, ASCII-имя) → scp →
  `ssh <сервер> 'bash /tmp/<файл>.sh'`. Без heredoc, `$(...)` и вложенных
  кавычек через PowerShell. Код возврата — от нужной команды (`set -euo pipefail`).
- Версии зависимостей прибиты, `latest` не используется. Новые пакеты —
  только существующие, с историей и репозиторием (проверить).
- Повторный запуск не плодит дубли (записи, задачи, находки) — идемпотентность.
- Тестовые данные помечать и убирать после проверки.
- Неиспользуемые зависимости и мёртвый код — удалять (с «да»).
- Сгенерированные файлы (клиенты ORM, сборка) — перегенерировать после
  изменения схем, иначе ложные ошибки.
- Не подавлять ошибки (`except: pass`, отключение проверок) вместо исправления причины.
- Тест, который просто повторяет объявление или конфиг и меняется вместе с кодом, — не
  защита, а балласт; тестировать поведение на стыке частей.
- У скрипта, который правит файлы, не бывает безобидного запуска «посмотреть, что получится»:
  для осмотра писать отдельный скрипт, который только читает и печатает. Правящий скрипт
  запускать, когда уже решено менять, и после — проверять результат, а не отчёт скрипта.
- Бэкап считается сделанным только после проверки самого архива (`gzip -t`, размер, число строк)
  и до первого изменения данных. Пустой архив от сломанной команды выглядит как успешный.
- Массовое переименование задевает текст: после него искать английские слова внутри русских
  фраз и проверять по отрисованной странице, а не по исходнику.
- Команды в документах и скриптах — только запущенные и проверенные.
