# Безопасность (с первого дня)

- Каждое серверное действие и API проверяет вход и права первой строкой —
  не полагаться на скрытые кнопки в интерфейсе.
- Сертификаты проверяются (без `verify=False` / `rejectUnauthorized: false`);
  плохой сертификат — обработать как ошибку.
- Секреты — только в `.env` или хранилище, в коде — имена переменных; `.env` в
  `.gitignore`; чужие ключи и токены в базе — шифровать. Файл `.env` создаёт и
  заполняет владелец (Claude его не читает и не пишет); Claude ведёт `.env.example`
  с именами переменных и говорит, что куда вписать; строка о новом доступе — в таблицу
  «Доступы» в KNOWLEDGE.md (без значений).
- Ввод пользователя проверять на сервере; запросы к базе — параметрами,
  не склейкой строк.
- Персональные, медицинские, платёжные данные: минимум полей, доступ по
  ролям, журнал доступа, требования закона (например 152-ФЗ) — уточнить в ТЗ.
- Логи — без паролей, токенов и персональных данных.
- Чужая боевая база (заказчика, партнёра, стороннего сервиса) — только чтение, пока владелец
  словами не разрешил запись: подключение поднимать в режиме «только чтение» на стороне
  сервера (`default_transaction_read_only=on` и подобное), чтобы отказ давал сервер, а не наша
  внимательность. Временная таблица, роль «для удобства», индекс «чтобы быстрее» — тоже запись.
  Результаты писать в файлы у себя. Персональные данные не выгружать: структура, справочники,
  счётчики строк; образец — 1–2 записи и только по отдельному «да». Разрешили запись в одну
  базу — перед каждой записью проверять имя текущей базы и в другие не писать.
- Публичные адреса — только https; внутренние адреса (192.168.x.x) не
  выдавать в коде, который работает у внешних пользователей.
- Зона повышенного риска (вход и права, деньги, файлы, внешние запросы, шифрование, чужие данные): после правки
  перечитать её отдельно и назвать в ответе «Риск: …».
- Пути из ввода (имя файла, адрес) — нормализовать и ограничить каталогом (path traversal); пользовательский текст
  экранировать по контексту вывода (HTML, атрибут, SQL, shell, URL); SSRF — внешние адреса из ввода по списку.
- Ошибки наружу — без stack trace, путей и текста запросов; подробности — в журнал.
