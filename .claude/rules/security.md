# Безопасность (с первого дня)

- Каждое серверное действие и API проверяет вход и права первой строкой —
  не полагаться на скрытые кнопки в интерфейсе.
- Сертификаты проверяются (без `verify=False` / `rejectUnauthorized: false`);
  плохой сертификат — обработать как ошибку.
- Секреты — только в `.env` или хранилище, в коде — имена переменных; `.env` в
  `.gitignore`; чужие ключи и токены в базе — шифровать. Файл `.env` создаёт и
  заполняет владелец (Claude его не читает и не пишет); Claude ведёт `.env.example`
  с именами переменных и говорит, что куда вписать; строка о новом доступе — в таблицу
  «Доступы» в KNOWLEDGE.md (без значений).
- Ввод пользователя проверять на сервере; запросы к базе — параметрами,
  не склейкой строк.
- Персональные, медицинские, платёжные данные: минимум полей, доступ по
  ролям, журнал доступа, требования закона (например 152-ФЗ) — уточнить в ТЗ.
- Логи — без паролей, токенов и персональных данных.
- Публичные адреса — только https; внутренние адреса (192.168.x.x) не
  выдавать в коде, который работает у внешних пользователей.
