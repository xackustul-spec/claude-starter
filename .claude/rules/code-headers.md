# Подпись файлов кода

- Первая строка комментария в каждом файле кода:
  `Назначение: <что делает файл, одной строкой>`.
  Из этих строк собирается карта проекта поиском по «Назначение:» —
  поэтому формулировка точная и короткая.
- Для неочевидных файлов (точки входа, интеграции, сложная логика, обходы
  ошибок библиотек) — ещё 1–4 строки: **почему так**, с чем связан, какие
  побочные эффекты (база, сеть, файлы). Не пересказывать код.
- Публичные функции, классы, компоненты — однострочное описание
  (docstring / JSDoc): что делает и что возвращает.
- Изменил поведение → обнови подпись в том же изменении. Устаревшая подпись
  хуже отсутствующей.
- В шапке — назначение, «почему так», связи, побочные эффекты. Не писать: цифры, даты,
  историю, факты, которые живут в другом месте (они устаревают).
- Не подписывать сгенерированные файлы (сборка, миграции, lock-файлы).
- Язык комментариев — русский; имена в коде — только латиница.
- Существующий проект: подписывать файлы, когда их меняешь, а не массовой правкой.
