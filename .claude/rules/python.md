# Python (PEP 8, типы, ошибки) — для нового и изменяемого кода

Чужой старый код целиком не переписывать: правило действует на то, что пишешь или правишь. Сверка — `code-check`.

- **Типы:** аннотации у всех новых и изменённых функций (аргументы и результат); `Any` — только с комментарием
  «почему». Проверка типов — `mypy` (в `--strict` для нового модуля), если он есть в проекте.
- **Docstring** (Google-стиль: `Args`, `Returns`, `Raises`) у публичных функций, классов и модулей; первая
  строка — «что делает», не пересказ имени.
- **Стиль:** PEP 8, строка до 100 символов; `ruff` (проверка + сортировка импортов) и `black`, если есть в
  проекте; без предупреждений в изменённых файлах. Импорты — стандартные, сторонние, свои, по алфавиту.
- **Ошибки:** никакого голого `except:` и `except Exception:` без `raise`. Ловить конкретное исключение, писать в
  журнал с контекстом, пробрасывать `raise … from err` или возвращать контролируемую ошибку.
- **Журнал:** `logging` с уровнями (DEBUG/INFO/WARNING/ERROR), не `print()` (кроме скриптов-утилит, чей вывод и
  есть результат). Без секретов и персональных данных в сообщениях.
- **Константы и настройки:** числа и строки с смыслом — именованными константами `MAX_RETRIES = 3` или в настройках
  (`pydantic-settings` / переменные окружения); пароли, ключи, строки подключения — только из окружения.
- **Вход извне** (форма, API, файл, чужая БД) — проверка и приведение типов на входе (`pydantic`); внутри кода данные
  уже проверены.
- **Деньги** — `Decimal`; время — с часовым поясом, текущее время передаётся параметром в расчёт; пути — `pathlib`;
  ресурсы (файл, соединение) — `with`; изменяемые значения по умолчанию в аргументах запрещены.
- **Ещё:** `dataclass`/`pydantic` вместо словарей «на глаз»; `is None`, не `== None`; без `import *`; без глобального
  изменяемого состояния; генераторы для больших выборок; `subprocess` без `shell=True` с вводом; `requests` — с
  `timeout`; `assert` не для проверки ввода; тесты — `pytest`, имя `test_что_условие_результат`.
