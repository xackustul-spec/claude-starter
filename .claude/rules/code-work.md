# Как работать с кодом (порядок, честность, тесты, отчёт)

Правила проекта (CLAUDE.md, PROJECT_MAP, соседний код) выше этого списка. Приоритет при конфликте: безопасность и
корректность → понятность → простота → скорость → краткость.

1. **Сначала разобраться, потом писать.** Прочитать соседний код и найти, как в проекте уже сделано то же; решить, в
   каком слое и модуле живёт правка; затронутые места и риск назвать одной строкой. Не переписывать не просили.
2. **Не выдумывать.** Файлы, функции, API, флаги библиотек, результаты команд — только те, что видел (Read/Grep/запуск).
   Не знаешь — проверить или сказать «не знаю». Нет данных для расчёта — спросить, не подставлять.
3. **Границы системы.** Ввод извне — проверка на входе (тип, размер, диапазон); внешние вызовы — таймаут и повтор с
   паузой; запись в базу/платёж/письмо — идемпотентна (повтор не удваивает: ключ операции, `upsert`, уникальный
   индекс) и в транзакции; время хранить в UTC, показывать в поясе пользователя; деньги — `Decimal`/целые копейки.
4. **Размеры — сигнал, не запрет.** Файл больше ~400 или функция больше ~40 строк — повод проверить: одна ли
   ответственность, низка ли сложность, нет ли дублей, понятны ли зависимости. Цельную функцию на 60 строк не кромсать
   ради цифры; смесь задач на 20 строк — разделить.
5. **Тесты.** Исправляешь ошибку — сначала тест, который её воспроизводит, потом правка. Тесты не ослаблять и не
   удалять, чтобы «позеленело». Нельзя запустить — писать «НЕ ПРОВЕРЕНО» и почему, не «должно работать».
6. **Зависимости и скорость.** Новая библиотека — только если нужна и жива (`compat-check`); запрос в цикле, чтение
   всего файла в память, лишний проход — не писать; измерять, а не гадать, прежде чем оптимизировать.
7. **Git.** Не коммитить и не пушить без слов владельца; коммит — Conventional Commits, только пути задачи.
8. **Отчёт о коде** (одна короткая строка на пункт): что изменено · `code-check` · тесты PASSED / FAILED / NOT RUN
   (с причиной) · что не проверено · риск или «Заметил».
