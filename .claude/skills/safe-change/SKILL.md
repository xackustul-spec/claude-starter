# Безопасное изменение

Правка в одном файле без внешних связей — только шаги 4–6. Пустой репозиторий без кода —
шаг 1 пропустить (ломать нечего).

## 1. До изменения: «что я сломаю?»
- Изменение в 1–2 фразах и ≤3 допущения.
- Субагент `impact-analyst` (чистый контекст, не тратит историю): для большой задачи —
  несколько по областям (код / стиль / данные / инфраструктура), не больше 3 параллельно.
- Ответ владельцу перед правкой (крупное — ждать «ок»): затронуто, риски, как проверим.

## 2. Снимок «до»
Коммит (чистое дерево) · итог проверок проекта · для интерфейса — скриншоты ключевых
экранов (`ui-checker`) в `docs/ai/previews/before/`.

## 3. Изменить — все места сразу
По списку из шага 1: код, импорты, конфиги, стили, тесты, скрипты, сборка, документы —
одним шагом. Переименование/перенос: обновить все ссылки; старый путь удалить или явное
перенаправление с датой удаления. «На потом» — только строкой в STATE.md.

## 4. Убедиться, что работает новое, а не старое
поиск (Grep) по старому имени/пути → нигде в коде · кеши сброшены, сгенерированное пересобрано,
сервисы перезапущены, веб — без кеша · отвечает новая версия (номер, изменённый текст, лог запуска).

## 5. Независимая проверка
`change-verifier` (план, старые пути, тесты, документы; запустить проект, не только читать);
интерфейс менялся — `ui-checker` (экраны, консоль, темы, телефон, сравнение с «до»).
Независимые — параллельно. Проблемы → исправить → повторить по проблемным пунктам.

## 6. Документы — в том же шаге
Шапка `Назначение:` у новых и изменённых файлов · STATE.md · что затронуто из KNOWLEDGE /
PROJECT_MAP / FOUNDATION / SPEC / DECISIONS / TOOLS / LESSONS · код и документы одним
коммитом (хук при завершении ответа напомнит).

## 7. Отчёт
Изменено · проверено (итоги команд, скриншоты) · затронуто рядом · осталось ·
«Заметил, не сделал». Поймал себя на оправдании → [stop-phrases.md](stop-phrases.md).
