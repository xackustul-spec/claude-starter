# Каркас проекта

Цель — у владельца полуготовый инструмент: стиль, шапка, меню, настройки и типовые
экраны есть, остаётся наполнять смыслом.

## 1. Найти все подходящие варианты (поиск + `compat-check`)
Стек берётся из SPEC «Стек» (нет — сначала предложить). Кандидаты — [catalog.md](catalog.md),
актуальность и версии проверять в интернете (не больше 3 запросов на библиотеку).
Таблица: подходит ли стеку · сколько тем · редактор тем · готовые блоки (шапка, меню,
таблица с фильтрами, карточки показателей, формы, настройки) · лицензия · активность · вес.
Отметить рекомендуемый.

## 2. Показать, а не описать (все варианты сразу)
- Каждому варианту — превью `docs/ai/previews/<вариант>.html` по образцу
  [preview-template.html](preview-template.html): шапка, меню, показатели, таблица со
  статусами, форма, кнопки, состояния «загрузка / пусто / ошибка», переключатель всех тем.
  Из CDN — только библиотеки с CDN-сборкой (daisyUI, Bootstrap/Tabler, Ant Design UMD…);
  для остальных (shadcn, Mantine, MUI) — ссылки и 2–3 скриншота официальной витрины,
  имитацию помечать словом ИМИТАЦИЯ. Мини-проект ради превью — только с «да».
- Галерея `docs/ai/previews/index.html` по образцу [gallery-template.html](gallery-template.html):
  вкладки, «компьютер / телефон», сравнение двух рядом. Открыть владельцу
  (встроенный браузер / Chrome / `start`, `open`, `xdg-open`); скриншоты светлой и тёмной
  темы — если есть браузерный инструмент (иначе владелец открывает файл сам).
- Пометка «пример данных». Выбор владельца → DECISIONS.md.

## 3. Библиотека и темы
- **Библиотека** — компоненты и их код; **тема** — цвета, шрифты, скругления поверх них.
- В проект ставится **одна** библиотека: две разные дают разные кнопки и таблицы,
  конфликтуют стилями, не переключаются без двойной вёрстки.
- Внутри неё подключить **все её темы** плюс фирменную — переключатель на странице
  настроек с мгновенным предпросмотром; выбор сохранять (для пользователя или для всего
  приложения — спросить). Разные «лица» — темами одной библиотеки.

## 4. Собрать каркас (по шагам, каждый — коммит; в пустом репозитории `impact-analyst` пропускать)
0. **База вёрстки** — `base.css` из этой папки подключается первой (border-box, картинки не шире
   экрана, таблица в `.table-wrap` с прокруткой, `min-width: 0` у детей flex/grid, перенос длинных
   слов, mobile-first с точками 480/768/1024/1280). Контейнеры — `width: 100%; max-width`, не
   фиксированная ширина; `position: absolute/fixed` — только для точечных элементов, не для каркаса;
   `<meta name="viewport" content="width=device-width, initial-scale=1">` в каждом документе.
1. **Тема** — единый файл токенов (цвета, тёмная тема, шрифты, размеры, радиусы, отступы).
2. **Оболочка** — шапка, меню (боковое/верхнее), область контента, подвал; телефон.
3. **Настройки** — выбор темы из всех подключённых с предпросмотром, светлая/тёмная/системная,
   основной цвет, язык, профиль; применяется ко всему проекту сразу.
4. **Вход** — если в ТЗ есть пользователи: готовая библиотека, роли, выход, проверка на сервере.
5. **Состояния** — «загрузка», «пусто», «ошибка», «нет доступа», 404.
6. **Витрина** — страница со всеми компонентами и цветами темы; новые экраны — только из неё.
7. **Шаблоны экранов** — список с поиском и фильтрами, карточка, форма, дашборд — на
   тестовых данных с пометкой. `ui-checker` — один раз после шага 6 и после шага 7.

## 5. Зафиксировать
`docs/ai/FOUNDATION.md` (библиотека, темы, где тема, витрина, ключевые экраны),
DECISIONS.md, TOOLS.md. Правила интерфейса уже в `.claude/rules/ui.md` — дописать туда
только то, чего требует выбранная библиотека (с «да»).

## Существующий проект
Не переделывать всё сразу: описать текущий стиль, найти расхождения между экранами,
предложить перенос в единую тему по одному экрану.
