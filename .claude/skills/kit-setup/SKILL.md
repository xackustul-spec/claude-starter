# Первый запуск набора

Выполняется и по `/kit-setup`, и по чтению этого файла из `INSTALL.md`: прочитал — делать шаги самому, сразу.

Цель: после этого скилла набор работает в проекте, файлы владельца целы, есть коммит, к которому
можно вернуться. **Установка вопросов не задаёт** (слова владельца 22.10: «он не должен задавать вопросы…
должен сразу понимать, как работать»): файл владельца перед изменением копируется в
`docs/ai/archive/<дата>/`, выбор по умолчанию записывается в STATE.md «Допущения» и в итог; владелец
поправит словами. Единственный вопрос — папка не похожа на проект (шаг 0). Удаление временных папок
набора — не вопрос, а одно окно разрешения. Материалы проекта (передачи, ТЗ, старые записи) в установку
не читать — только то, что нужно для PROFILE и STATE, по одному файлу «где остановились».

## 0. Та ли это папка
Набор ставится в папку одного проекта. Проверить текущую папку до любых действий:
- Похоже на проект: есть код, `package.json`, `pyproject.toml`, `composer.json`, `.git`; или в папке
  только `_starter/` (и, может быть, материалы владельца) — это папка нового проекта, код и материалы
  владелец добавит потом → дальше, шаг 0.1, без вопроса.
- Похоже на общую папку: имя вроде `Claude`, `Documents`, `Desktop`, `Downloads`, домашняя
  папка пользователя; внутри несколько подпапок, каждая со своим кодом или `.git`; кода в
  корне нет → **остановиться и спросить владельца**: «Ставим в папку конкретного проекта.
  Какой это проект и где он лежит?» Варианты в вопросе: перечислить найденные подпапки-проекты
  и «создать новую папку для нового проекта».
- Владелец назвал новый проект по-русски → предложить папку латиницей рядом с текущей:
  имя из названия (перевод или транслитерация, строчными, через дефис: «Счета» → `billing`,
  «СЕО панель» → `seo-panel`), русское название сохранить в паспорте PROFILE.md. Создать папку
  после «да» и дальше работать в ней.
- Claude Code открыт не в той папке — сказать владельцу, какую открыть: набор ставится там,
  где он запущен.

## 0.05. Не идёт ли установка уже
- Есть `.claude/starter.lock` (файл с датой и папкой) моложе 30 минут, или в папке уже лежат
  файлы набора вместе с `_starter/` — возможно, установку ведёт другой сеанс Claude.
  Продолжить здесь (метку переписать) и сказать об этом строкой в итоге.
- Начиная работу, создать `.claude/starter.lock` (дата, ОС, папка), в конце шага 3 — удалить.
  В `.gitignore` метка уже исключена строкой `starter.lock` из `gitignore.starter`.

## 0.1. Где лежит набор
- Набор уже в корне нужной папки (есть `.claude/skills/kit-setup/`) → шаг 1; подпапка `_starter/` осталась —
  удалить её, повторно не переносить.
- Архив набора распакован прямо в корень проекта (в корне `INSTALL.md`, `VERSION`, `.gitignore` набора с
  заголовком «Это исходник claude-starter») → убрать `INSTALL.md` и `README.md` набора (README
  владельца не трогать), `.gitignore` набора заменить строками `gitignore.starter` плюс файлы с секретами и
  архивы, которые владелец положил в папку; дальше — шаг 1. Повод: CRM 22.10 — хук принял такой проект за
  исходник набора и запрещал в нём работать.
- Подпапка `_starter/` уже есть до начала установки → взять свежую: сравнить `_starter/VERSION`
  с источником; отличается или непонятно — удалить папку и скачать заново.
- Набор в подпапке (обычно `_starter/`) → сначала коммит проекта «до набора» (нет git — `git init`; файлов
  проекта нет — коммит не нужен), затем перенести в корень по правилам:

| Файл набора | Нет у владельца | Есть у владельца |
|---|---|---|
| `CLAUDE.md` | скопировать | файл владельца → копия в `docs/ai/archive/<дата>/CLAUDE.project.md`; его правила → `.claude/rules/project.md` правилом по 1–3 строки (ничего не потерять, без истории), описание проекта → PROFILE/KNOWLEDGE; ядро набора → `CLAUDE.md`. `CLAUDE.starter.md` не заводить |
| `.claude/settings.json` | скопировать (ОС не Windows — взять `settings.unix.json`) | положить как `.claude/settings.starter.json` |
| `.mcp.json` | скопировать | добавить только сервер `context7`, остальное не трогать |
| `.claude/rules|agents|skills|hooks/*` | скопировать | одноимённый файл владельца не заменять; файл набора положить рядом как `<имя>.starter.md` и назвать в итоге |
| `docs/ai/*` | скопировать | не заменять; недостающие файлы добавить |
| `gitignore.starter` | строки, которых нет, дописать в `.gitignore` (создать, если нет) | то же |
| `STARTER.md`, `SEARCH.md`, `AUDIT-PROMPT.md` | скопировать | — |
| `README.md`, `INSTALL.md`, `.git/`, `inbox/`, `VERSION`, `CHANGELOG.md` набора | не копировать | не копировать |
| `README.md` проекта | не трогать | не трогать |

  После шага 3 (отпечатки) — удалить подпапку набора и любые другие распакованные копии набора в папке: иначе её `CLAUDE.md` и скиллы будут
  подгружаться второй раз. Дальше — сразу шаг 1 в этом же разговоре, без перезапуска
  (инструкции этого файла уже прочитаны; хуки из настроек подхватываются сами).

## 1. Окружение (только чтение)
- ОС. Windows → хуки `.ps1` в `.claude/settings.json`. Linux/macOS/Git Bash → в
  `settings.json` должны стоять хуки из `settings.unix.json`: если `settings.json` — копия
  набора, заменить целиком; если это файл владельца (есть `settings.starter.json`) —
  не трогать, хуки перенесёт `project-adopt`. Пока `settings.starter.json` не слит, хуки набора
  не действуют: живую проверку шага 3 не делать — её выполнит `project-adopt` после слияния.
- Python 3 (нужен тестам хуков, а на Linux/macOS — самим хукам): Windows — `py -3 --version`,
  затем `python --version` (не `python3`: на Windows это ярлык магазина); Linux/macOS —
  `python3 --version`. Git: `git --version`.
- Git: нет `.git` → `git init`; `.gitignore` — по `gitignore.starter` (см. шаг 0).
- Работающий проект? Есть код и чужие инструкции: `AGENTS.md`,
  `.cursor/rules`, `.github/copilot-instructions.md`, `.clinerules`, старые `.claude/`.
- Context7: сервер из `.mcp.json` Claude Code предлагает одобрить при старте сеанса; не
  одобрен или нет сети — работать через WebSearch/WebFetch.

## 2. Профиль — без вопроса, по умолчанию
Доверие «обычное», ответы «сжато», код «не показывать»; «Смотрю результат» и «выкладывать самому» — из
материалов проекта (адрес боевого), нет — «—». Записать в `docs/ai/PROFILE.md` («подтверждено
владельцем: по умолчанию при установке») и одной строкой в итог: «профиль по умолчанию: …; поменять — скажите».
Паспорт — что видно из папки; неизвестное — «—», не «TODO» (TODO в PROFILE и STATE хук при старте читает
как «набор не установлен» и снова зовёт /kit-setup).
Владелец назвал уровень сам — записать его («подтверждено: да»).
- Осторожное → `.claude/settings.local.json`: `{"permissions": {"defaultMode": "default"}}`
  (правки файлов тоже будут спрашиваться).
- Полное → `.claude/settings.local.json`: `{"env": {"CLAUDE_TRUST_LEVEL": "full"}}` и
  подсказать включить режим Auto (STARTER.md, «Профиль»).
- Сжато → можно добавить в тот же файл `"outputStyle": "Concise"`, если такой стиль есть в `/config`.
- Файл личный: `settings.local.json` уже в `.gitignore`, в git и на другой компьютер не попадёт.
  Claude пишет его сам, целиком (Write), без вопросов — но только эти ключи: доверие из PROFILE.md,
  `defaultMode`, `outputStyle`. Любые другие ключи (разрешения, хуки) — вопрос владельцу.
  Файл уже есть — прочитать, дописать нужный ключ, записать целиком. Настройки вступят в силу после /clear,
  о котором и так просит последняя строка отчёта.
- Паспорт в PROFILE.md: что видно из папки; остальное — после /clear (`project-adopt` или слова владельца).
- Удалить из docs/ai строки-подсказки и примеры шаблонов, которые больше не нужны.

## 3. Проверить набор и закоммитить (до любой другой работы)
- Полный прогон тестов хуков при установке не делать (10 минут и много токенов): он для выпуска набора.
- Живую проверку хуков в сеансе установки не делать: хуки подхватываются только новым сеансом. Проверка —
  после /clear: в начале сеанса есть строка `[claude-starter] Старт сеанса`.
- STATE.md: «Сейчас», «Следующий шаг», `head:` = текущий короткий sha; ни одного «TODO» (неизвестное — «—»).
- Версия и отпечатки файлов набора: `python3 .claude/hooks/kit_hooks.py manifest <папка набора> <источник>`
  (Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File .claude\hooks\kit-version.ps1 manifest …`);
  источник — ссылка на GitHub, откуда набор обновляется (по умолчанию
  `https://github.com/xackustul-spec/claude-starter`); никогда не «.» и не временная папка. Делать до удаления
  подпапки набора; набор был сразу в корне — папка набора = корень.
- Коммит `chore: набор claude-starter подключён` — точка отката.

## 4. Дальше — после очистки, не в этом сеансе
Установка съедает контекст (у CRM 22.10 — 200 тыс. токенов до первой задачи). Поэтому дальше работать
с чистого листа:
- STATE.md: «Главная задача: —»; «Следующий шаг»: новый проект — `project-intake`, работающий —
  `project-adopt` (слить инструкции и настройки, заполнить docs/ai тем, чего не видно из кода), либо
  то, на чём владелец остановился в своих материалах (одной строкой, с путём к файлу).
- Последняя строка отчёта: «Набор установлен — наберите /clear, затем «продолжай»».

## 5. Отчёт владельцу (сжато)
Что настроено · что ждёт «да» · что не удалось и как проверить вручную · следующий шаг ·
замеченное рядом — строкой в STATE.md, «Заметил».
