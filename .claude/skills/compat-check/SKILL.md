# Совместимость: $ARGUMENTS

## 1. Что уже есть
Версии языка, фреймворка и ключевых пакетов (lock-файлы, `--version`), ОС, где будет
работать. Прочитать docs/ai/TOOLS.md и DECISIONS.md — нет ли уже решения. Если в проекте
есть свой документ правил совместимости — сверяться с ним и дополнять его.

## 2. Найти по свежим источникам (не по памяти; ≤3 запроса на пакет)
- Пакет существует, ему не 2 недели, есть репозиторий и история (модели придумывают
  имена пакетов, злоумышленники их регистрируют).
- Актуальная стабильная версия и дата (Context7, официальный сайт, страница релизов).
- Требования: версии языка/рантайма/фреймворка, peer-зависимости, ОС.
- Breaking changes между нашей и нужной версией (changelog, руководство по миграции).
- Известные проблемы: GitHub Issues «<пакет> <наш фреймворк> <версия>», недавние.
- Лицензия и поддержка (последний релиз, активность).

## 3. Вывод
Таблица: компонент → версия → совместимо (да / нет / с условием) → риски → источник.
Итог: ставить ли, какую версию прибить, что может сломаться и как проверить.

## 4. После «да» (при полном доверии — сразу)
Прибить версию (без `latest` и широких диапазонов) → установить → запустить проверки
проекта, показать вывод → строка в TOOLS.md → грабли в LESSONS.md.
