# Агенты-специалисты

Агент знает только то, что в задании и что найдёт сам. Поэтому специалиста делает **роль + стандарт + свежий поиск
+ форма ответа**, а не слова «проверь код». Агент `specialist` всё это уже умеет; от тебя — задание.

## Задание (до шести строк; хук пропускает только с первыми четырьмя «Задача / Где / Вернуть / Стоп»)
```
Роль: <специалист какой области; чьи стандарты; с какой точки зрения смотрит>
Задача: <одно действие: проверить / найти / оценить достроенность>
Где: <конкретные файлы или папки — только свои, чужие не трогать>
Вернуть: Неверно · Не хватает · Готовое · Стыки (файл:строка, вес) · «Проверено: …»
Стоп: <когда закончить; «проблем нет» — допустимый ответ>
```
Слова владельца — цитатой; свои догадки в задание не писать. Предел вызовов задаёт хук: поиск — 15; с «Роль:» — 25
(читать файлы + 1–2 поиска свежей практики); агенту, который **строит или правит**, — строка `Объём: до N вызовов`
(N до 60: файлы части × ~4 вызова на файл, но не больше 60).

## Роли (примеры строки «Роль»)
- **Безопасность:** «аудитор безопасности веб-приложений (OWASP Top 10, ASVS): вход, пароли и сессии, права, ввод, секреты».
- **Данные:** «специалист по базам (схема, индексы, транзакции, миграции, целостность данных)».
- **Интерфейс:** «специалист по интерфейсу: доступность, состояния (пусто/ошибка/загрузка), привычные образцы».
- **Производительность:** «специалист по скорости: лишние запросы, N+1, тяжёлые циклы, кеш».
- **Надёжность:** «специалист по отказам: ошибки сети, повторы, таймауты, потеря данных при сбое».
- **Архитектура:** «специалист по структуре кода: слои (данные / расчёт / вывод / стиль), формулы в одном месте, деньги в Decimal, настройки в окружении — по `rules/architecture.md`».
- **Своя роль** — любая область так же: специалист какой области, по какому стандарту, что ищет.
Новую роль, которая пригодилась, — одной строкой сюда же.

## Порядок
1. Разбей файлы по областям (не по папкам): файл может попасть в две роли — это нормально, лишь бы каждая смотрела
   своё. Агентов — по числу областей, не больше пяти; запускать вместе, в одном сообщении.
2. Каждому — своё задание. Целиком проект не отдавать.
3. Свести ответы: убрать повторы, **проверить 2–3 самые серьёзные находки сам** (открыть место), прежде чем
   показывать владельцу; непроверенное пометить.
4. **Проход по стыкам:** собрать раздел «Стыки» всех агентов и проверить связку (где логин, где проверка прав, где
   данные) одним отдельным заданием или самому. Дыры чаще на стыках.
5. «Взять готовое» — владельцу вопросом с выбором только если решение меняет структуру; иначе в план.
6. Агенты ничего не правят. Исправления — основной сеанс, по плану, с `change-verifier`.

## Крупная работа: делить на части, чтобы агент не упёрся в предел
Агент имеет своё окно и свой предел. Агент, которому дали «весь проект», останавливается на середине — это ошибка
деления, а не агента. Поэтому:
1. **Часть = один результат, до ~8 файлов или ~60 КБ чтения.** Больше — делить дальше. Части не пересекаются по
   файлам: два агента не правят один файл.
2. **Сначала договорённость, потом деление.** Для постройки: интерфейсы между частями (имена функций, поля, формат
   данных) записать до запуска; части собираются сверху по этой договорённости. Слои — по `rules/architecture.md`
   (данные → расчёт → вывод): расчёт и вывод разными агентами только когда границу между ними уже записали.
3. **Волнами.** Не больше 5 агентов одновременно; следующая волна — после сведения предыдущей. Таблица «часть ·
   файлы · агент · статус» — в документе главной задачи: после обрыва видно, что сделано.
4. **Результат — в файл, не только в ответ** (агент, который пишет, кладёт итог в `docs/ai/solutions/<тема>-<часть>.md`
   или в сами файлы). Ответ — коротко: что сделано, что не сделано (список файлов), что нужно.
5. **Агент упёрся в предел** («нужно: …» или остаток в ответе) — новый агент на остаток: «Где» = только недоделанные
   файлы. Основной сеанс не доделывает за него сам: он дороже и тянет контекст.
6. **Модель по части:** механическая правка и поиск — Sonnet; решение, сверка денег, безопасность — Opus.
7. Свести: проверить 2–3 главных результата самому, прогнать тесты, затем `change-verifier` на всём вместе.
