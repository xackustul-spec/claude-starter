# Проверка кода по своду

Одна команда по изменённым файлам (без аргументов — все изменённые по `git status`), замечания только по
изменённым строкам и функциям:
- Linux/macOS/Git Bash: `python3 .claude/skills/code-check/check.py [файлы]`
- Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File .claude\skills\code-check\check.ps1 [файлы]`

Проверяет: файл до 400 строк, функция до 40; `print`/`console.log` в боевом коде; голый `except:` и `except Exception:`
без `raise`; пустой `catch`; `var`, `==`, `any`; пароли, ключи, токены в тексте; Python — аннотации типов и docstring
у новых функций; запускает `ruff`, если он есть в проекте.

## Порядок
1. Запустить. Замечание по новому или изменённому коду — исправить сразу; по старому коду рядом — «Заметил» в STATE.
2. Ложное срабатывание (константа, тест, утилита, чей вывод — результат) — одна строка в ответе, почему не исправлено.
3. В ответе: «Код-проверка: N замечаний → исправлено / не исправлено: что» и «Тесты: PASSED / FAILED / NOT RUN (почему)»; не запускал — «НЕ ПРОВЕРЕНО».
4. Линтеры проекта (`ruff`, `mypy`, `eslint`, `tsc`, `prettier`) — если есть в проекте, прогнать на изменённых файлах.

## Коммит
Conventional Commits: `feat: …`, `fix(sync): …`, `refactor(db): …`, `docs: …`, `chore: …`, `test: …`. Один коммит — одно
логическое изменение (не «fix all»); сообщение — что и зачем, одной строкой. Код с замечаниями в коммит не идёт.
Коммитить только пути своей задачи (явный список файлов).
